你正在看的这个博客，是我在对前端几乎一无所知的情况下，从一个空仓库搭起来的。这篇记录一下整个过程的选型、思路和踩过的坑——如果你也想写博客但被「前端」吓住，希望它能帮你少绕一点路。

## 为什么是静态站点

我的本行是 Java / Spring Boot。习惯了「服务器常驻、请求进来动态渲染」的思路后，第一反应总是：写博客得先买个服务器，跑个 WordPress，或者自己写个 Spring 应用？

其实完全不用。静态站点生成器把这件事变成了**构建时**的一次性动作：Markdown 文章在构建时就渲染成了纯 HTML，部署后没有任何后端进程。没有服务器要维护、没有数据库要备份，也不担心被打——代码托管在 GitHub，免费。

对 Spring Boot 开发者，心智模型可以这样对照：

| Spring Boot | 静态站点 |
| --- | --- |
| 请求时动态渲染 | 构建时一次性生成 HTML |
| Controller 处理路由 | `src/pages/` 下的文件就是路由 |
| Service 业务逻辑 | 页面文件顶部 `---` 里的一段脚本 |
| 数据库 | 无，文章就是 `.md` 文件 |
| `java -jar` | `npm run build` |

## 技术选型

- **Astro 5**：内容优先的静态站点框架，默认零 JS 发到浏览器，构建飞快（这个站全量构建不到 1 秒）
- **Tailwind CSS 4**：原子化 CSS，直接在 HTML 里写样式
- **Giscus**：评论系统，数据存在 GitHub Discussions，零后端
- **GitHub Pages + Actions**：推送即部署

原计划用 Vercel，后来想想代码本来就托管在 GitHub，就顺手用了 GitHub Pages——对静态站点来说它们都只是个免费 CDN。

## 踩过的坑

### 浏览器打开 RSS 显示一堆 XML？

不是 bug。RSS 本来就是给阅读器消费的机器格式，浏览器直接打开显示文档树是正常行为。不过为了对人类友好，我单独做了一个订阅页，可以一键复制订阅地址。

（中间还尝试过给 XML 注入 XSL 样式表的方案——本机 `xsltproc` 验证转换完全正确，但实测发现有些浏览器环境不会应用 XSLT，最终放弃了。）

### GitHub Pages 的子路径

仓库叫 `my-blog`，所以站点地址是 `https://mureromi.github.io/my-blog/` 而不是根路径。这意味着 Astro 配置里要加一行 `base: '/my-blog'`，并且**全站所有内部链接都要跟着加前缀**，不然本地好好的，一上线全是 404。

### 私有仓库用不了免费的 Pages

免费版 GitHub Pages 只对公开仓库开放，私有仓库需要 GitHub Pro。个人博客本来就是要公开的，直接把仓库设为公开即可——而且 Giscus 评论也只支持公开仓库。

### Giscus 未配置时会把报错暴露给访客

评论组件的配置（repo、repo-id 等）没填之前，页面上会出现一坨报错。我加了个守卫：配置还是占位值就跳过加载。有意思的是 esbuild 在构建时就把这个判断折叠掉了——未配置的加载代码在产物里根本不存在。

## 这个博客的样子

界面走的是「极客终端风」：等宽字体、方角、细边框。页头是一个带闪烁光标的 `mureromi@blog:~$`，首页用 `$ ls -t ~/posts/` 列出文章，文章页用 `$ cat ~/posts/xxx.md` 打开正文。深浅双主题手动切换，选择会被记住。

代码块用了 shiki 双主题，语法高亮的配色会跟着站点明暗一起切换。
